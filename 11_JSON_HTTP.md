## Краткая теория

JSON — текстовый формат обмена данными. Ключи объектов записываются в двойных кавычках. В JSON используются `true`, `false`, `null`, а в Python — `True`, `False`, `None`. Файл с одинарными кавычками и `None` является записью Python, но не корректным JSON.

| Python | JSON |
|---|---|
| `dict` со строковыми ключами | Объект |
| `list` | Массив |
| `str` | Строка |
| `int`, конечный `float` | Число |
| `bool` | `true` / `false` |
| `None` | `null` |

`json.load(file)` читает из файла, `json.loads(text)` разбирает строку. `json.dump(data, file)` записывает в файл, `json.dumps(data)` возвращает строку. Кортеж при записи превращается в JSON-массив, который читается обратно как список.

```python
# json_example.py
import json

data = {"title": "Учебная задача", "completed": False}
text = json.dumps(data, ensure_ascii=False, indent=2)
restored = json.loads(text)
assert restored == data
print(text)
```

`ensure_ascii=False` сохраняет читаемую кириллицу, `indent=2` задаёт отступ. При работе с файлами дополнительно указывайте `encoding="utf-8"`. Синтаксически правильный JSON может содержать неправильную для вашей задачи структуру: её проверяют отдельно.

## HTTP: управляемое упражнение

HTTP-запрос получает ответ сервера. Метод GET используется для чтения ресурса. Статус `200` означает успешный ответ, `404` — ресурс не найден; `403` или `429` могут потребовать проверки ограничений доступа или частоты запросов.

Здесь получаем **профиль пользователя GitHub по логину**, а не данные репозитория. Для репозитория потребовались бы владелец и имя репозитория, это другой ресурс API. Внешние библиотеки и токен для этого учебного запроса не нужны.

Сохраните `fetch_profile.py`:

```python
import json
import socket
from pathlib import Path
from urllib.error import HTTPError, URLError
from urllib.parse import quote
from urllib.request import Request, urlopen


def fetch_profile(login):
    if not login.strip():
        raise ValueError("Логин не должен быть пустым")
    url = "https://api.github.com/users/" + quote(login.strip(), safe="")
    request = Request(url, headers={
        "Accept": "application/vnd.github+json",
        "User-Agent": "python-course-lab11",
    })
    with urlopen(request, timeout=10) as response:
        data = json.loads(response.read().decode("utf-8"))
    if not isinstance(data, dict) or not isinstance(data.get("login"), str):
        raise ValueError("Ответ не похож на профиль пользователя")
    return data


def main():
    try:
        data = fetch_profile(input("Логин GitHub: "))
        output = Path(__file__).resolve().parent / "profile.json"
        with open(output, "w", encoding="utf-8") as file:
            json.dump(data, file, ensure_ascii=False, indent=2)
        print(f"Профиль сохранён: {data['login']}")
    except HTTPError as error:
        print(f"Сервер вернул HTTP {error.code}")
    except (URLError, TimeoutError, socket.timeout):
        print("Не удалось получить ответ по сети")
    except (ValueError, UnicodeError) as error:
        print(f"Ошибка данных: {error}")
    except OSError as error:
        print(f"Ошибка доступа: {error}")


if __name__ == "__main__":
    main()
```

Запустите один запрос для `octocat`, если интернет доступен. Не проверяйте изменяемые поля профиля на точное совпадение с чужим примером. В README объясните назначение адреса, GET, таймаута и обработчиков ошибок.

Если сети нет, создайте `profile_sample.json` с содержимым `{"login": "demo", "id": 1, "name": null}`, прочитайте его через `json.load` и выведите логин. Укажите, что использованы учебные локальные данные. Это равноценный режим выполнения упражнения; отсутствие интернета не снижает оценку.
