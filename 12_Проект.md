## Цель и объём

## Формат данных

Файл `data.json` содержит список записей следующего вида:

```json
[
  {"id": 1, "title": "Основная задача", "category": "учёба", "amount": 4, "completed": false},
  {"id": 2, "title": "Дополнительная задача", "category": "учёба", "amount": 2, "completed": true}
]
```

Это пример структуры для варианта 1. Для других вариантов замените названия, категории и значения на подходящие вашей области.

Правила:

- `id` — положительное целое, уникальное внутри списка.
- `title`, `category` — строки, непустые после `strip()`; при добавлении убирайте пробелы по краям.
- `amount` — целое число не меньше нуля; логические значения не принимаются вместо чисел.
- `completed` — строго `bool`.
- Корень JSON — список, каждая запись — словарь. Все пять ключей обязательны; дополнительные ключи можно сохранять без обработки.
- Для новой записи используйте `max` существующих идентификаторов плюс 1; для пустого списка — `1`. Идентификаторы существующих записей не перенумеровывайте после удаления.

## Обязательные возможности

Консольное меню работает в цикле до команды выхода. Неправильная команда вызывает сообщение и повторный показ меню.

1. **Показать записи.** Для каждой записи вывести ID, название, категорию, количество с единицей измерения и статус. Порядок — по возрастанию ID. Для пустого списка — `Нет записей`.
2. **Добавить запись.** Запросить название, категорию и количество. Повторять некорректный ввод. Начальный статус `False`. Одинаковые названия разрешены, ID различаются.
3. **Найти записи.** По непустой подстроке названия без учёта регистра. Пустой поисковый запрос отклонить. Ничего не найдено — понятное сообщение.
4. **Изменить статус.** Найти запись по ID и явно установить выбранное пользователем значение «выполнено» или «не выполнено». Неизвестный ID не меняет данные.
5. **Удалить запись.** Удаление по ID после подтверждения `да`. Любой другой ответ отменяет действие. Неизвестный ID — сообщение без изменения списка.
6. **Показать статистику.** Общее количество записей, число выполненных и невыполненных, сумма `amount` по всем записям и суммы по категориям. Категории выводить по алфавиту; сравнивать их точно после удаления краевых пробелов.
7. **Сохранить данные.** Записать текущий список в JSON в UTF-8. Сообщать об успехе только после успешной записи.
8. **Выйти.** Предложить сохранить текущие данные: при ответе `да` выполнить сохранение; при ошибке записи остаться в меню. Ответ `нет` завершает программу без записи. Другой ответ повторяет вопрос.

При запуске загрузите `data.json` из папки проекта и проверьте весь набор до начала работы. Если файла нет, начните с пустого списка и сообщите об этом. Если файл повреждён, имеет неправильную кодировку или структуру, выведите причину и завершите запуск **без перезаписи файла**. Исправление входного файла выполняется отдельно.

## Рекомендуемая структура

```text
project/
    main.py
    logic.py
    storage.py
    test_logic.py
    test_storage.py
    data.json
    README.md
```

| Модуль | Ответственность |
|---|---|
| `logic.py` | Проверка записей, добавление, поиск, статус, удаление и статистика |
| `storage.py` | Чтение и запись JSON, без консольных диалогов |
| `main.py` | Меню, ввод, сообщения, вызовы функций |

Возможные функции: `validate_records(records)`, `add_record(records, title, category, amount)`, `find_records(records, query)`, `set_completed(records, record_id, completed)`, `delete_record(records, record_id)`, `statistics(records)`, `load_records(path)`, `save_records(path, records)`.

Зафиксируйте контракты в строках документации: какие функции изменяют список, что возвращают при успехе и при неизвестном ID. Например, изменение статуса и удаление могут возвращать `True` при успехе и `False`, если запись не найдена. Поиск и статистика исходные данные менять не должны. Не используйте изменяемые глобальные переменные для хранения состояния.

1. Создайте 3–5 вымышленных записей и определите ожидаемую статистику вручную.
2. Реализуйте функции обработки и тесты без меню и файлов.
3. Добавьте чтение, проверку и сохранение JSON. Проверьте повторную загрузку.
4. Соберите консольное меню и повторный ввод при ошибках.
5. Пройдите сценарии приёмки, исправьте найденные ошибки, оформите README.

## Сценарии приёмки

| Сценарий | Ожидаемое поведение |
|---|---|
| Файла нет | Пустой список, меню доступно |
| JSON содержит `[]` | Список пуст, статистика: все количества и сумма равны 0 |
| Добавлены записи с количеством 4 и 2, вторая завершена | Всего 2, выполнена 1, невыполнена 1, сумма 6 |
| Название введено как `  Python  ` | Сохранено `Python` |
| Поиск `PY` при названии `Python` | Запись найдена |
| Пустое название, `amount=-1`, `amount=abc` | Повторный ввод, лишняя запись не появляется |
| Изменение статуса неизвестного ID | Сообщение, данные не изменены |
| Удаление отменено | Запись сохранена |
| Удалена запись с ID 1 из списка с ID 1 и 2 | Оставшаяся запись сохраняет ID 2; следующая новая получает ID 3 |
| Сохранение и перезапуск | Все поля и статусы восстановлены |
| Повреждённый JSON или повторный ID | Запуск прекращён с сообщением; файл не изменён |
| Ошибка сохранения | Нет сообщения об успехе; программа позволяет продолжить работу |

В автоматических тестах проверьте обработку пустого списка, повторяющихся названий, строгие типы полей, неизвестный ID, поиск без учёта регистра и статистику по двум категориям. Проверяйте сохранение и повторное чтение во временной папке через `TemporaryDirectory()`. Меню проверьте вручную по таблице.

## Дополнительное задание: графический интерфейс

Добавляйте GUI только после готовности обязательной версии. Можно сделать окно поиска и просмотра записей, используя готовую `find_records()`. Не переносите в обработчик кнопки всю логику проекта.

Для знакомства запустите `python -m tkinter`. Если компонент отсутствует, установите Tcl/Tk средствами вашей среды или пропустите дополнительное задание.

Минимальный отдельный пример окна:

```python
# gui_example.py
import tkinter as tk
from tkinter import ttk


def main():
    root = tk.Tk()
    root.title("Проверка интерфейса")
    value = tk.StringVar()
    result = tk.StringVar(value="Введите название")

    def show_title():
        title = value.get().strip()
        result.set(title if title else "Название не должно быть пустым")

    ttk.Entry(root, textvariable=value).pack(padx=12, pady=8)
    ttk.Button(root, text="Показать", command=show_title).pack(pady=8)
    ttk.Label(root, textvariable=result).pack(padx=12, pady=8)
    root.mainloop()


if __name__ == "__main__":
    main()
```

`command=show_title` передаёт функцию, а `command=show_title()` немедленно вызвало бы её при создании кнопки. `mainloop()` запускает обработку событий. Проверьте пустой ввод, кириллицу, повторные нажатия и закрытие окна. Дополнительный интерфейс не заменяет консольную версию и не требуется для 10 баллов.

Справка: [tkinter](https://docs.python.org/3/library/tkinter.html).
